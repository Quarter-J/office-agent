# 已完成改动说明

更新日期：2026-09-16。本文汇总已落地的 Top-k 检索、路由分发、超时、Agent 冲突与长上下文处理，说明对应行为、代码位置与验证范围。

## 1. Top-k 检索

解决的问题：检索入口对 Top-k 的处理不统一，向量检索异常与未命中容易混淆，生成回答失败时可能丢失已找到的资料。

已完成：

- Top-k 默认值为 **3**，仅接受 **1–20 的整数**；拒绝布尔值、数字字符串、小数和越界值。工具参数与直接检索调用共用校验规则。
- 片段检索与 RAG 共用检索流程：先向量检索，结果为空或发生异常时尝试关键词检索。
- 检索结果统一提供 `source`、`score`、`content`、`rank`。不同检索方法的分数含义不同，不跨方法直接比较。
- 区分正常命中、未命中、错误和超时；“没有找到”不会被当作工具故障，工具故障也不会被伪装成未命中。
- 已检索到资料但模型回答失败时，保留资料和来源供用户查看。

Top-k 表示最多返回多少条结果。相似度阈值过滤后可以少于 k 条，甚至为零，不强行凑满结果。

主要代码：[参数校验](../src/rag/validation.py)、[检索工具](../src/tools/search.py)、[向量检索](../src/rag/vector_store.py)、[SearchAgent](../src/agent/sub_agents/search_agent.py)。

## 2. 路由分发与任务交接

解决的问题：历史消息或工具结果可能干扰当前意图，生成与发送的先后顺序缺少约束，业务动作与宽泛关键词容易混淆。

已完成：

- 以最新一条用户消息划分当前轮次；Supervisor 读取用户原始指令，委派说明仅作为补充。
- 具体业务规则优先处理“生成日报”“查询日报”“添加知识库”等请求，避免仅根据宽泛关键词误分发。
- 修复分类提示词中 JSON 花括号造成的格式化错误；校验模型返回的意图枚举，无效时使用业务规则降级。
- “生成内容后发送”先完成生成，再交给 MessageAgent。传递完整正文；日报还保留文件路径。
- 同批工具包含委派时优先交给主管，其他工具不执行，并为每个调用返回匹配的 ToolMessage。
- 当前允许的子 Agent 后续交接为发送节点；节点完成后清理交接状态。
- 每轮最多执行 **3 批工具调用**，新轮次重新计数。已完成工具后模型出错时，保留工具结果，不重新分派整项任务。
- 缺少平台、接收人或正文时请求补充；QQ群发送可只提供群号。发送失败、超时、结果未知或发生冲突时保留已生成正文。

主要代码：[当前轮次与意图辅助函数](../src/agent/context.py)、[工作流](../src/agent/graph.py)、[Supervisor](../src/agent/sub_agents/supervisor.py)、[内容交接](../src/agent/delivery.py)、[消息 Agent](../src/agent/sub_agents/message_agent.py)、[日报 Agent](../src/agent/sub_agents/report_agent.py)。

## 3. 工具与任务超时

解决的问题：单次网络超时不足以约束整轮任务，阻塞工具可能持续运行，发送超时后盲目重试可能重复发送。

已完成：

- CLI 和 Web UI 接入 `run_agent`，由父进程监督可复用的工作进程。超过任务或操作时限时终止工作进程，下次请求重新启动。
- 排队、进程启动、模型、工具、记忆处理和重试均计入整轮预算。模型、嵌入与 HTTP 请求使用各自上限，并受剩余预算约束。
- 模型 SDK 自动重试关闭；只读请求允许在同一预算内有限重试。
- 操作开始前与父进程确认，避免发送已经开始却未被监控记录。已确认成功的回执不会因后续操作超时而变为未知。
- QQ 建立连接超时返回未发送；等待响应超时、连接中断或响应含义不明确时返回 `unknown`，不自动重发。仅明确的 HTTP 404/405 允许尝试兼容接口。
- 中断时尽量保留已完成结果、生成正文和报告路径。

主要代码：[执行入口](../src/agent/runner.py)、[预算与工具包装层](../src/utils/execution.py)、[消息工具](../src/tools/message.py)、[配置](../src/config/settings.py)。配置默认值、状态含义及集成方式见 [执行时限与超时结果](execution-timeouts.md)。

## 4. Agent 冲突与重复动作

解决的问题：只在 MessageAgent 检查无法覆盖 Router 直接调用工具；不同执行路径可能重复发送，进程重启后也需要保留动作状态。

已完成：

- 两条 Agent 执行路径共用动作检查：发送意图、禁止发送约束、生成前置条件、已确定的正文与目标均参与校验。
- 同批调用给出不同发送方案或对同一文件给出不同写入方案时，在执行前暂停相关动作；独立查询继续完成。相同动作合并执行，各调用仍获得对应结果。
- SQLite 原子记录任务、步骤、执行拥有者、方案和回执。同一任务步骤成功后复用回执；明确失败、执行中或结果未知时不自动再次执行。
- 使用同一数据库的进程共享文件占用记录；知识库写入同时占用共享向量索引。调用方可传入文件版本，拒绝覆盖已变化的文件。
- 冲突记录包含来源 Agent、双方方案、原因和裁决；规则可解决的路由冲突继续执行，其余动作冲突返回 `conflict`。
- 进程中断后保留未知状态；提供不向模型开放的维护接口，在核实外部结果后更新记录并释放资源。

主要代码：[冲突规则](../src/agent/conflicts.py)、[动作记录](../src/utils/action_ledger.py)、[任务状态](../src/agent/state.py)。任务 ID 的复用、文件版本检查、维护接口及边界见 [Agent 冲突处理](agent-conflicts.md)。

这些辅助模块没有增加 Agent 角色：项目仍为 Router、Supervisor、ContentAgent、MessageAgent、ReportAgent、SearchAgent、ChatAgent 共 **7 类**。

## 5. 长上下文与滚动摘要

解决的问题：记忆摘要没有替代原始聊天历史，模型输入没有总预算；旧摘要不断追加，已摘要消息未移除，内存回退的负索引裁剪还可能清空历史。

已完成：

- 在模型请求序列化处统一控制输入预算，计入系统指令、消息、工具定义、工具回执与需要回传的推理字段；预留输出和安全余量，并实际限制输出长度。
- 只裁剪模型输入副本；按完整轮次移除旧历史，保留当前指令和工具调用参数，工具调用与回执不会拆散。工具结果可缩短正文，但保留状态、ID 和来源。
- 将记忆及检索片段与固定系统指令分开；摘要覆盖的旧历史不再全部重传，尚未摘要的近期轮次继续保留。
- 将旧摘要和新增旧消息合并成有字符上限的新摘要。长历史分段处理，全部成功后原子提交摘要并移除对应消息；并发追加保留，过期快照不提交。
- 修复内存回退的 `ltrim(..., -1)`；配置中的旧 `*_TURNS` 名称保持兼容，并明确其单位为消息条数。
- 服务端明确拒绝上下文长度时，只在模型层缩减输入并重试一次，受原有时间预算限制，不重跑工具。无法容纳当前请求或模型输出不完整时停止继续分派。

主要代码：[上下文预算](../src/api/context.py)、[模型接口](../src/api/llm.py)、[记忆管理](../src/memory/manager.py)、[短期记忆](../src/memory/short_term.py)。默认配置、使用方式与限制见 [长上下文处理](context-management.md)。

## 7. 当前边界

- 自然语言意图与目标检查采用有限规则；尚未实现资料之间的事实矛盾自动裁决、通用任务规划或澄清后的自动续跑。
- 每个任务目前支持一个发送方案。新任务 ID 代表新请求；同一任务重试必须保留原任务 ID 才能复用动作记录。
- 本地去重不能撤销远端已经接收的消息，也不能保证远端严格只执行一次。结果未知时仍需核实。
- 单个 Runner 串行处理请求。硬终止会丢失工作进程内的临时缓存，文件和数据库保留。
- 直接调用原始 LangGraph 不具有进程级硬超时；直接调用底层工具也不会自动获得 Agent 任务上下文。独立集成方式见对应专题文档。
- 上下文计数采用保守文本估算，摘要与资料截取可能损失细节；无法容纳的当前指令需要分段或先入库检索。真实模型和 Redis 路径尚未联调。
- 企业微信、钉钉、邮件、周报/月报汇总和定时调度仍为预留能力；长期记忆的关键词回退及文档元数据问题不在本轮修正范围内。
